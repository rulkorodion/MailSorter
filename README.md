# Mail Sorter — сортировка почты с Ollama или Cloud.ru

Серверная утилита на Python: подключается к почтовым ящикам по IMAP, классифицирует письма через локальную Ollama или Cloud.ru Foundation Models и в явно подтверждённом Active Mode раскладывает их по папкам.

- Один процесс: веб-интерфейс + фоновый опрос
- Несколько ящиков — изолированные конфиги в `configs/`
- Windows Server (Планировщик заданий)
- Без базы данных, без Docker

---

## Быстрый старт (Windows)

```bat
:: 1. Распакуйте в C:\mail-sorter (или любую папку)
cd C:\mail-sorter

:: 2. Установка
scripts\install.bat

:: 3. Запуск
scripts\run.bat
```

Откройте в браузере: **http://localhost:8080**

При первом запуске (папка `configs/` пуста) откроется **мастер настройки**:
1. Данные IMAP-почты
2. Провайдер ИИ и модель
3. Категории и папки
4. Логин/пароль веб-интерфейса

После сохранения конфига включается обычный вход (Basic Auth).
Шаблон конфига: `configs/example.yaml.example` (можно скопировать вручную при необходимости).

### Планировщик заданий

1. Откройте «Планировщик заданий» → Создать задачу
2. Триггер: «При запуске компьютера» или «При входе в систему»
3. Действие: запуск `C:\mail-sorter\scripts\run.bat`
4. Рабочая папка: `C:\mail-sorter`
5. Отметьте «Выполнять независимо от входа пользователя» (при необходимости)

## Конфигурация ящика

Каждый файл `configs/*.yaml` — отдельный ящик. Основные секции:

| Секция | Назначение |
|--------|------------|
| `name` | Отображаемое имя |
| `imap` | Хост, порт, логин, пароль, INBOX, Unsorted, интервал |
| `folder_layout` | `inbox` для новых ящиков; отсутствие поля сохраняет старое размещение папок |
| `llm`  | Провайдер, модель, лимит токенов, таймаут и повторы |
| `rules`| Порог уверенности + список категорий → папок |
| `web`  | Хост/порт веб-интерфейса, логин/пароль |
| `logging` | Уровень, файл, размер ротации |

**Пароль:** задавайте через переменную окружения: `password: "ENV:MAIL_PASSWORD"`. Только такая ссылка заставляет приложение прочитать `MAIL_PASSWORD`; если в YAML указана обычная строка, она передаётся IMAP как пароль, а переменная не используется. Старые конфиги с открытым значением ещё загружаются, но должны быть перенесены на защищённое хранение.

В Windows задайте `MAIL_PASSWORD` в окружении **того процесса, который запускает Mail Sorter**, до запуска `scripts\run.bat` или задачи Планировщика. Переменная, заданная после запуска, не появится в уже работающем процессе; `setx` влияет только на новые процессы. Не вводите пароль прямо в команду, сохраняемую в истории оболочки. Если IMAP отклоняет вход, в разделе «Конфигурация» проверьте показанный источник пароля и используйте «Проверить подключение» — приложение не показывает значение секрета.

**Папки:** В новых конфигурациях `folder_layout: inbox`: простое имя категории (например `Доступы`) означает подпапку INBOX с фактическим разделителем сервера (`INBOX/Доступы` либо `INBOX.Доступы`). Полный путь (`INBOX/Доступы`) остаётся явным назначением. Конфигурации без `folder_layout` работают по-старому: простой путь остаётся в корне, указанные пути не меняются. Кириллицу кодирует `imap-tools` (IMAP UTF-7). `unsorted_folder: Unsorted` в новой конфигурации аналогично размещается внутри INBOX. Ничего не мигрирует и не удаляется автоматически.

На странице «Папки» выберите ящик и нажмите «Проверить структуру»: увидите существующие и недостающие полные IMAP-пути и готовность. Для создания только отсутствующих папок нажмите «Создать недостающие» и введите показанное подтверждение. Права IMAP CREATE должны быть у пользователя ящика; результат повторно сверяется с сервером. При ошибке или неполной структуре устраните проблему до Active. Повторная проверка/создание не создаёт дубликатов. Обычный опрос и Dry Run никогда не создают папки; Active не перемещает письмо в отсутствующую папку.

**Логика обработки:**
1. Все письма из INBOX (независимо от флагов)
2. Классификация через выбранного провайдера → JSON `{category, confidence, reason}`
3. При ошибке модели или JSON письмо остаётся в исходной папке; Cloud.ru повторяет только временные ошибки в заданных пределах
4. Если `confidence >= threshold` и категория известна → предполагаемая папка категории
5. При низкой уверенности известной категории или корректном отказе модели от выбора → `unsorted_folder`; неизвестная категория или ошибка LLM оставляет письмо в источнике
6. В Dry Run выводится план без изменений почты; в явно подтверждённом Active выполняется перемещение

## Безопасность

### Cloud.ru Foundation Models на Windows

Сервис использует [Cloud.ru chat completions](https://cloud.ru/docs/foundation-models/ug/topics/api-ref) по HTTPS. Для `openai/gpt-oss-120b` конфиг:

```yaml
llm:
  provider: cloudru
  model: openai/gpt-oss-120b
  base_url: https://foundation-models.api.cloud.ru/v1
  api_key: ENV:CLOUDRU_FOUNDATION_MODELS_API_KEY
  max_tokens: 2048
  timeout_seconds: 120
  max_retries: 3
```

`max_tokens` переводится в `max_completion_tokens` и включает reasoning-токены. Для Cloud.ru `temperature` по умолчанию **не передаётся**: поддержка зависит от модели. При необходимости добавьте её явно в YAML после проверки выбранной модели. Существующие YAML без `provider` продолжают работать с Ollama.

Ключ вводите только в переменную окружения процесса, не в YAML и не в команду с открытым текстом. В PowerShell перед запуском:

```powershell
$secureKey = Read-Host "Cloud.ru API key" -AsSecureString
$plainKey = [System.Net.NetworkCredential]::new("", $secureKey).Password
[Environment]::SetEnvironmentVariable("CLOUDRU_FOUNDATION_MODELS_API_KEY", $plainKey, "Process")
Remove-Variable secureKey, plainKey
.\scripts\run.bat
```

Ключ наследуется запущенным приложением; после закрытия этой сессии PowerShell переменная пропадёт. Для службы или Планировщика заданий настройте безопасную передачу переменной окружения отдельно. Ключ не отображается в интерфейсе и логах. При отсутствии ключа тест модели выдаёт понятную ошибку.

Откройте `http://127.0.0.1:8080`. В мастере выберите Cloud.ru или в существующем ящике откройте «Конфигурация» → «Провайдер модели», выберите Cloud.ru и модель. Переключение сбрасывает режим в Dry Run. Кнопка «Проверить модель» посылает только искусственный текст, **без IMAP**; затем на странице «Тестирование» можно классифицировать вручную введённый искусственный пример и увидеть папку, причину, длительность и токены. Не вставляйте реальные корпоративные письма в этот тест без разрешения.

Выход модели строго проверяется по папкам `rules.destinations`. Невалидный JSON, пустая или неизвестная категория, усечённый ответ, HTTP/сетевая ошибка не перемещают письмо. Список параметров в общей OpenAI-совместимой схеме не гарантирует поддержку каждого параметра конкретной моделью; [документация Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/guides__llm-chat-request) показывает `max_completion_tokens` и `temperature`, но эту интеграцию следует отдельно проверить на выбранной модели.

- Пароль почты не пишется в логи
- Исключения LLM и IMAP журналируются без текста ответа модели, письма или секретов
- Веб защищён Basic Auth
- Рекомендуется запускать на изолированной машине / в закрытой сети

### Первый этап безопасной эксплуатации

После запуска каждый ящик находится в **Dry Run**. По расписанию и при ручном запуске письма читаются и классифицируются, но не перемещаются, не удаляются и не помечаются прочитанными. Предполагаемые папки и статистика видны на странице «Запуск». После перезапуска и после изменения конфига режим снова Dry Run.

Для реального перемещения на странице «Запуск» выберите «Включить Active» у нужного ящика и введите точную фразу `ACTIVE имя_файла.yaml`. Перед этим проверьте правила и результаты Dry Run. Кнопка «Вернуть Dry Run» останавливает новые перемещения. Уже начатый проход может завершиться в прежнем режиме.

Веб-сервер по умолчанию слушает `127.0.0.1:8080`. Мастер первой настройки доступен только с этого компьютера. Для доступа с другого компьютера настройте отдельный HTTPS reverse proxy и сетевую фильтрацию. IMAP TLS проверяется по умолчанию; для внутреннего CA добавьте его в доверенные сертификаты Windows.

При IMAP over TLS приложение последовательно проверяет DNS-адреса сервера (не более 8 адресов, до 10 секунд на адрес и в пределах общего таймаута `imap.timeout_seconds`). После успешного handshake тот же сокет передаётся `imap-tools`; для SNI и проверки сертификата всегда используется исходное доменное имя. Ошибка сертификата останавливает подключение, а ошибка IMAP-аутентификации не запускает перебор других IP. `imap.ssl_verify: false` теперь отклоняется: небезопасное подключение запрещено.

Для одного разрешённого теста проблемного IMAP MOVE можно включить структурную диагностику: до запуска приложения в PowerShell задайте `$env:MAILSORTER_IMAP_MOVE_DIAGNOSTICS = '1'`, затем запустите приложение обычным способом. После испытания удалите переменную командой `Remove-Item Env:MAILSORTER_IMAP_MOVE_DIAGNOSTICS` и перезапустите приложение. При `unexpected_response` в журнале появится `stage=move_response_shape` с длиной и признаками формата отвергнутой строки, **без самой строки**, тегов, учётных данных или содержимого письма. При передаче результата администратору сопоставьте записи по `session` и UID; не включайте низкоуровневый `imaplib.Debug`.

Редактор YAML скрывает сохранённые пароли маркером `<REDACTED>` и сохраняет старое значение, если маркер не менять. Кнопка «Проверить» восстанавливает скрытые значения из выбранного файла только в памяти, не записывая файл; сохранение делает то же перед валидацией. Новые IMAP-секреты лучше задавать как `ENV:MAIL_PASSWORD`. Созданные через мастер веб-пароли хранятся как PBKDF2-хеш; старые конфиги с открытым паролем продолжают работать и переходят на хеш при сохранении в редакторе.

Локальные `configs/*.yaml`, `logs/*`, `.env` и файлы ключей исключены из Git. В репозитории остаётся только пример конфигурации.

### Офлайн-тесты на Windows

После `scripts\install.bat` выполните из корня проекта:

```bat
venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют fake IMAP и fake LLM, поэтому не обращаются к почте и внешним API. Для ручной проверки Dry Run запустите `scripts\run.bat`, откройте `http://127.0.0.1:8080`, настройте тестовый ящик и сначала изучите страницу «Запуск» в режиме Dry Run. Ручной запуск и фоновое расписание всё же читают выбранный IMAP-ящик, поэтому используйте только разрешённый тестовый ящик.
