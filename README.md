# Mail Sorter — сортировка почты с локальным ИИ

Серверная утилита на Python: подключается к почтовым ящикам по IMAP, классифицирует письма через локальную Ollama и раскладывает их по папкам.

- Один процесс: веб-интерфейс + фоновый опрос
- Несколько ящиков — изолированные конфиги в `configs/`
- Windows Server (Планировщик заданий)
- Без базы данных, без Docker

---

## Быстрый старт (Windows)

```bat
:: 1. Распакуйте в C:\mail-sorter (или любую папку)
cd C:\mail-sorter

:: 2. Установка
scripts\install.bat

:: 3. Запуск
scripts\run.bat
```

Откройте в браузере: **http://localhost:8080**

При первом запуске (папка `configs/` пуста) откроется **мастер настройки**:
1. Данные IMAP-почты
2. Адрес Ollama и модель
3. Категории и папки
4. Логин/пароль веб-интерфейса

После сохранения конфига включается обычный вход (Basic Auth).
Шаблон конфига: `configs/example.yaml.example` (можно скопировать вручную при необходимости).

### Планировщик заданий

1. Откройте «Планировщик заданий» → Создать задачу
2. Триггер: «При запуске компьютера» или «При входе в систему»
3. Действие: запуск `C:\mail-sorter\scripts\run.bat`
4. Рабочая папка: `C:\mail-sorter`
5. Отметьте «Выполнять независимо от входа пользователя» (при необходимости)

## Конфигурация ящика

Каждый файл `configs/*.yaml` — отдельный ящик. Основные секции:

| Секция | Назначение |
|--------|------------|
| `name` | Отображаемое имя |
| `imap` | Хост, порт, логин, пароль, INBOX, Unsorted, интервал |
| `llm`  | Endpoint Ollama, модель, промпт, retries |
| `rules`| Порог уверенности + список категорий → папок |
| `web`  | Хост/порт веб-интерфейса, логин/пароль |
| `logging` | Уровень, файл, размер ротации |

**Пароль:** задавайте через переменную окружения: `password: "ENV:MAIL_PASSWORD"`. Старые конфиги с открытым значением ещё загружаются, но должны быть перенесены на защищённое хранение.

**Папки:** создаются автоматически, если отсутствуют. Поддерживаются вложенные (`INBOX/Work`).

**Логика обработки:**
1. Все письма из INBOX (независимо от флагов)
2. Классификация через Ollama → JSON `{category, confidence}`
3. При ошибке JSON — до 3 повторов
4. Если `confidence >= threshold` и категория известна → предполагаемая папка категории
5. При низкой уверенности или пустой категории → `unsorted_folder`; неизвестная категория или ошибка LLM оставляет письмо в источнике
6. В Dry Run выводится план без изменений почты; в явно подтверждённом Active выполняется перемещение

## Веб-интерфейс

| Страница | Возможности |
|----------|-------------|
| Обзор | Статус всех ящиков, быстрый запуск |
| Конфигурация | Редактор YAML с валидацией, сохранение «на лету» |
| Папки | Проверка/создание IMAP-папок |
| Запуск | Принудительный обход + live-статус |
| Тестирование | Классификация произвольного текста без перемещения |
| Логи | Хвост лога с автообновлением |

Авторизация: HTTP Basic (логин/пароль из конфига).

- Доступ к IMAP-серверу (порт 993)

## Безопасность

- Пароль почты не пишется в логи
- Исключения LLM и IMAP журналируются без текста ответа модели, письма или секретов
- Веб защищён Basic Auth
- Рекомендуется запускать на изолированной машине / в закрытой сети

### Первый этап безопасной эксплуатации

После запуска каждый ящик находится в **Dry Run**. По расписанию и при ручном запуске письма читаются и классифицируются, но не перемещаются, не удаляются и не помечаются прочитанными. Предполагаемые папки и статистика видны на странице «Запуск». После перезапуска и после изменения конфига режим снова Dry Run.

Для реального перемещения на странице «Запуск» выберите «Включить Active» у нужного ящика и введите точную фразу `ACTIVE имя_файла.yaml`. Перед этим проверьте правила и результаты Dry Run. Кнопка «Вернуть Dry Run» останавливает новые перемещения. Уже начатый проход может завершиться в прежнем режиме.

Веб-сервер по умолчанию слушает `127.0.0.1:8080`. Мастер первой настройки доступен только с этого компьютера. Для доступа с другого компьютера настройте отдельный HTTPS reverse proxy и сетевую фильтрацию. IMAP TLS проверяется по умолчанию; для внутреннего CA добавьте его в доверенные сертификаты Windows.

Редактор YAML скрывает сохранённые пароли маркером `<REDACTED>` и сохраняет старое значение, если маркер не менять. Новые IMAP-секреты лучше задавать как `ENV:MAIL_PASSWORD`. Созданные через мастер веб-пароли хранятся как PBKDF2-хеш; старые конфиги с открытым паролем продолжают работать и переходят на хеш при сохранении в редакторе.

Локальные `configs/*.yaml`, `logs/*`, `.env` и файлы ключей исключены из Git. В репозитории остаётся только пример конфигурации.

### Офлайн-тесты на Windows

После `scripts\install.bat` выполните из корня проекта:

```bat
venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют fake IMAP и fake LLM, поэтому не обращаются к почте и внешним API. Для ручной проверки Dry Run запустите `scripts\run.bat`, откройте `http://127.0.0.1:8080`, настройте тестовый ящик и сначала изучите страницу «Запуск» в режиме Dry Run. Ручной запуск и фоновое расписание всё же читают выбранный IMAP-ящик, поэтому используйте только разрешённый тестовый ящик.
