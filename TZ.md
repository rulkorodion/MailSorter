# Техническое задание: Mail Sorter

Краткое описание системы для ввода в курс дела (актуально на текущую версию проекта).

---

## 1. Назначение

**Mail Sorter** — серверная утилита на Python для автоматической сортировки писем.

- Подключается к почте по **IMAP**
- Классифицирует письма через **локальную LLM (Ollama)**
- Перемещает письма в папки по правилам
- Настраивается через **веб-интерфейс** (без БД, один процесс)

Не SaaS, не многопользовательский продукт. Рассчитан на один сервер (в т.ч. Windows Server) и несколько почтовых ящиков.

---

## 2. Основной сценарий

1. Письма читаются из **папки-источника** (обычно `INBOX`).
2. Локальная модель по единому system prompt выбирает **папку назначения**.
3. При достаточной уверенности письмо **перемещается** в эту папку.
4. Иначе — в `Unsorted`.

Правила задаёт пользователь: для каждой папки назначения — **условие на естественном языке**
(например: *«письма с требованием доступа к отчёту»*).
Система **сама собирает** из условий один system prompt.

---

## 3. Функции

| Область | Возможности |
|--------|-------------|
| **Ящики** | Несколько изолированных конфигов (`configs/*.yaml`) |
| **IMAP** | SSL (993), проверка подключения, опция `ssl_verify` |
| **Папки** | Дерево, создание / переименование / удаление (интерактивно) |
| **Правила** | Папка + условие; порог уверенности; папка-источник |
| **Автоправило** | По письмам в папке назначения: саммари → черновик условия → подтверждение |
| **Тест** | Классификация вручную или по письму из ящика |
| **Опрос** | По расписанию + «Запустить сейчас» |
| **Веб** | HTTP Basic Auth, мастер первой настройки |
| **Логи** | Файл с ротацией + просмотр в UI |

---

## 4. Архитектура

- **Один процесс:** FastAPI (веб) + фоновый опрос (APScheduler).
- **Без БД:** настройки только в YAML.
- **Стек:** Python 3.10+, FastAPI, imap-tools, httpx, PyYAML, APScheduler.
- **ИИ:** Ollama HTTP API (`/api/chat`), ответ строго JSON:
  `{"category": "путь_папки", "confidence": 0.0–1.0}`.

```
configs/*.yaml  →  manager  →  sorter  →  IMAP + Ollama
                     ↑
                 веб-интерфейс :8080
```

## 5. Конфиг ящика (упрощённо)

```yaml
name: "test.ai"
imap:
  host: mail.example.ru
  port: 993
  username: user@example.ru
  password: "..."          # или ENV:MAIL_PASSWORD
  inbox_folder: INBOX
  unsorted_folder: INBOX/Unsorted
  poll_interval_seconds: 60
  ssl_verify: true
llm:
  endpoint: http://localhost:11434
  model: qwen2.5:14b
rules:
  source_folder: INBOX
  confidence_threshold: 0.75
  destinations:
    - folder: INBOX/Work
      condition: "Рабочие письма, задачи, совещания"
web:
  admin_username: admin
  admin_password: "..."      # в новых конфигах хранится PBKDF2-хеш
```

---

## 6. Запуск (Windows)

1. `scripts\install.bat` — venv и зависимости
2. `scripts\run.bat` — веб + фоновый опрос
3. Браузер: `http://localhost:8080`
4. При пустой `configs/` — мастер настройки

Постоянная работа — через **Планировщик заданий** (запуск `run.bat`).

При каждом старте обработка включена в режиме Dry Run: письма анализируются, но не перемещаются. Active Mode включается отдельно для каждого ящика с явным подтверждением в веб-интерфейсе.

---

## 7. Ограничения

- Только текст письма (без вложений)
- Нет OAuth2 (логин/пароль IMAP)
- Нет Docker / Linux systemd в текущей поставке (ориентир — Windows + bat)
- Качество сортировки зависит от модели Ollama и формулировок условий
